- **[確定]** ユーザーの直近の要求、または過去に明示的に合意した振る舞い。受入の判断基準とする。

- **[要決定]** ユーザーの意図・選択が必要な事項。決まるまで確定仕様／合格条件へ昇格させない。
- **[要検証]** 期待する挙動は決まっているが、現行依存・実機・配信環境などで成立確認が必要な事項。
- **[現行事実]** 2026-10-11時点に確認した`main`のコード上の状態。本番・実機での動作保証ではない。

優先順位は **最新の明示要求 ＞ 過去の合意 ＞ 採用済み設計 ＞ 未採用の提案**。現行コードは日本語版保護の比較対象であり、過去の明示要求と食い違う箇所を無断で修正・追認しない。要決定事項は影響する工程の着手前にまとめて整理し、無関係な小PRを止めない。

## 1. 目的と変更しないもの

### 1.1 成功の定義 [確定]

**現在の日本語版の魅力・デザイン・機能を基本的にそのまま守り、英語でもNEKO DISCOとして自然に楽しめる体験を提供する。** 文字列が英語になるだけでは完了としない。

最優先の要求：

1. **日本語版を不要に変えない。** 文言、改行、配色、猫の配置、演出、操作、BGMの挙動を維持する。共通処理を触ったら日本語版を回帰確認する。
2. **言語選択UIを世界観に馴染ませる。** 形・配置は未決定。既存の音楽／モーション操作を押しのけず、かわいさ・遊び心・操作性を両立する案を画面で比較してから採用する。
3. **英語は完全な対訳でなくてよい。** 読みやすい長さと軽いユーモアを歓迎する。ただし事実・出典・調査条件・個体差・飼育上の注意・クイズの正誤を改変しない。

### 1.2 対象外 [確定]

- 猫種数・順位・画像・フロアの座標、クイズの正答、背景、演出、BGM音源の変更・追加制作。
- `public/music-samples.html`、`public/music-samples-loop.js`の翻訳。メインサイトのBGM再生に必要な音源は従来どおり利用する。
- 新しいサイト初期化／言語リセットUI、トラッキング、同意バナー、アカウント、プレイ進捗の永続保存。
- 旧技術スパイクの大規模CDP診断コードを製品機能として移植すること。

## 2. URL・言語判定・ナビゲーション

### 2.1 URLの意味 [確定]

| URL                                        | 契約                                                                                                     |
| ------------------------------------------ | -------------------------------------------------------------------------------------------------------- |
| `/`                                        | 有効な手動選択Cookie → `Accept-Language` → 日本語の順に言語を決め、同一サイトの`/ja`か`/en`へ**307**転送 |
| `/ja`                                      | 日本語を明示。Cookie・ブラウザ言語による上書き禁止                                                       |
| `/en`                                      | 英語を明示。Cookie・ブラウザ言語による上書き禁止                                                         |
| 未対応のアプリケーションページ／言語ルート | **404**。日本語へ黙って転送しない（既存の静的公開ファイル等は対象外）                                    |

- [確定] 言語ルーティングによる404判定は未対応のアプリケーションページ・言語ルートに限定する。既存の`public/`配下の公開ファイル（音源試聴ページを含む）、画像・音源・favicon等の静的アセット、フレームワーク内部パスを言語判定で遮断・転送しない。既存の配信経路を維持する。
- [確定] ブラウザの`navigator.language`でサーバーの決定をハイドレーション時に上書きしない。明示言語URLの直接アクセス・再読み込みはその言語を維持する。
- [確定] 入口の307はクエリ文字列を順序・重複値も含めて引き継ぐ。サーバーはハッシュを受け取れないため、ブラウザによるフラグメント継承は実ブラウザで確認する。
- [設計候補／英語基盤の判定テスト確定前に要決定] `Accept-Language`の詳細評価：`ja`/`ja-*`と`en`/`en-*`、有効なq値の降順、`q=0`除外、同率はヘッダー順、非対応・不正な要素は無視、候補なし／`*`のみは日本語。**優先順位自体は確定しているが、このパース規則の承認状況は別に確認する。** 未承認のまま必須テストとして固定しない。
- [設計候補／ルート接続前に要決定] `/ja/`・`/en/`をスラッシュなしへ正規化する場合のステータスと、検索・共有URLへの影響。`/ja`・`/en`の役割自体は変えない。

### 2.2 通常の言語切替 [確定]

**JavaScript有効の同一タブでの通常の手動切替は、ソフトナビゲーションと第4節の状態継続を必須とする。** 失敗した場合、フルリロードへ黙って切り替えたり状態保持を削減したりせず、代替案の承認を求める。

- 切替先は`/ja`・`/en`の実URL。元のクエリは重複値を含め維持し、ハッシュも引き継ぐ。
- 同じアンカーIDがある場合は対応セクションへ、ハッシュがない場合は先頭へ。ピクセル単位のスクロール位置は保持しない。
- 戻る・進むでは履歴先の明示URLを尊重し、手動切替用のスクロール制御で履歴復元を上書きしない。
- 同じ言語の再選択はCookieのみ更新し、ナビゲーション・再読込・プレイ状態の初期化をしない。
- 明示URLの閲覧・直接アクセス・リロード・履歴移動・プリフェッチを手動選択と誤認しない。

## 3. Cookieとリンク操作

### 3.1 保存仕様 [確定]

| 項目     | 値                                                          |
| -------- | ----------------------------------------------------------- |
| 名前／値 | `neko_disco_locale` = `ja` または `en`（小文字のみ）        |
| 有効期間 | `Max-Age=15552000`（180日）                                 |
| 属性     | `Path=/`、Domainなし（host-only）、`SameSite=Lax`           |
| Secure   | HTTPS本番／プレビューではあり、HTTPローカルではなし         |
| 書込み   | 明示的な手動言語選択に伴う`document.cookie`。`HttpOnly`なし |
| 読取り   | 言語自動判定入口のサーバー／Worker処理                      |

- 自動判定・閲覧・直アクセス・リロード・履歴操作・プリフェッチではCookieを作成・延長しない。他タブのCookie変更を理由に表示中のタブを切り替えない。
- 不正な値、重複して曖昧な値は「有効な保存なし」。自由なパス生成に使わない。
- 言語設定を`localStorage`や`sessionStorage`へ重複保存しない。
- 保存できなくても明示URLへの切替を妨げない。保存結果は読み戻し等、確認できる範囲で確認する。**書込みAPI呼び出し＝成功とみなさない**。失敗を検出できた場合は短い補助通知を表示し、検出不能な状況を成功確認済みと誤記しない。
- 現在、サイト側リセットUIはないので追加しない。将来の明示的な日本語復帰操作を作る場合は、Cookieを削除するのではなく`ja`を書き`/ja`へ移動する（通常リロードはリセットではない）。

### 3.2 操作別の契約 [確定／保証範囲]

| 操作                                   | 言語表示・画面                                                    | Cookie保存                                                     |
| -------------------------------------- | ----------------------------------------------------------------- | -------------------------------------------------------------- |
| 通常クリック／Enter（JS有効）          | 同じタブでソフト遷移。状態を継続                                  | 明示操作として更新                                             |
| 現在言語を再選択                       | URL・画面・状態を維持                                             | その言語へ更新                                                 |
| 修飾クリック／中央クリック             | リンク本来の新規タブ等の動作を妨げず、移動先の明示URLで言語を保証 | 捕捉可能な明示操作では更新。捕捉不能な環境での保存は保証しない |
| 右クリックメニュー「新しいタブで開く」 | 移動先URLの言語を保証                                             | 保存保証なし                                                   |
| JS無効時のリンク操作                   | 実際に操作可能な`/ja`・`/en`リンクで到達可能                      | 保存保証なし。クエリ／ハッシュの自動引継ぎも保証しない         |
| 直接URL・リロード・戻る／進む          | URLで言語を決定。通常の履歴挙動を維持                             | 更新しない                                                     |

- 言語選択UIの基本リンクは実際の`href`を持つ。**DOMにリンクがあるだけでなく、JS無効時もユーザーが操作できる**ことを確認する。JS必須でしか開かないメニューを唯一の導線にしない。
- 修飾・中央クリックで現在タブの表示やプレイ状態を変えない。Cookieの更新契機はユーザー操作のみで、prefetchや表示時の副作用にしない。
- [要確認／言語選択UI接続前] 修飾・中央クリックでCookieが更新されると、**元のタブは日本語のままでも次回の`/`アクセスは英語になり得る**。これは以前の操作仕様を引き継いだもので、今回勝手に変更しない。挙動を変更する希望がある場合はUI接続前に確認する。

## 4. 言語切替中の状態

### 4.1 同一タブの通常切替で保持 [確定]

| 状態                                 | 受入条件                                                                                                                                                                        |
| ------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| BGM                                  | **作成済み**の実プレイヤー・AudioContextを言語切替で破棄・再生成しない。再生中は途切れ・再スタート・重複再生なく再生位置を維持する。**未生成**の初回OFF状態では生成を要求しない |
| `off`／`loading`／`playing`／`error` | 各状態と進捗を維持。`off`は未生成と停止後の両方を扱う。既存リソースがある場合はその継続性を確認し、切替だけで新規生成・自動再生・自動再試行・意図しない中断を起こさない         |
| 発見済み猫種                         | 同じ猫種ID集合・進捗を維持                                                                                                                                                      |
| クイズ                               | 問題位置、回答内容、得点、完了状態を維持。英語に変わっても選択肢と正解の対応を保持                                                                                              |
| 猫の時間帯                           | 明示的な手動選択を維持。新規セッションの初期判定は**日本時間（JST）**を継続                                                                                                     |
| モーション                           | 手動設定と`prefers-reduced-motion`の既存優先規則を維持                                                                                                                          |

### 4.2 切替時に閉じる [確定]

- **実際に言語遷移が発生した場合**、開いている猫種・生態の詳細モーダルやシーンのツールチップを閉じる。モーダル表示中に背後の言語UIを操作できることや、モーダル内に新しい言語切替ボタンを追加することは要求しない。
- フォーカスは破棄済みDOMに戻さず、移動先の適切な操作要素へ戻す。キーボード利用者の現在位置が分かるようにする。

### 4.3 保証外と実装候補

- [確定] フルリロード、新規タブ、ブラウザ再起動をまたぐプレイ状態の永続化は不要。
- [現行事実] `app/page.tsx`にプレイ状態が集中し、`useDiscoAudio`は音楽操作時にプレイヤーを遅延生成し、アンマウント時に破棄する。初回OFFではプレイヤー・AudioContextが未生成であり、そのままページを差し替えただけでは再生中の継続を保証できない。
- [設計候補／要検証] 共通Root配下で状態・プレイヤーを継続させるProvider等。必要なUI更新とSSRの言語別`html lang`を両立させる。音楽停止／保存復元方式へ無断で変更しない。

## 5. 翻訳の範囲・品質・データ整合性

### 5.1 翻訳対象 [確定]

| 領域               | 必須となるテキスト・データ                                                                                                                                                        |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 猫種12件           | `name`、`catchphrase`、`intro`、`trait`、`appearance`、`personality`、`detail`に相当する表示文言。既存`english`名は適切なものを維持                                               |
| 猫の生態12件       | `label`、`tag`、`title`、`body`、`tip`、`sound`を表示文脈で監査。既に自然な英語の演出ラベルは維持可                                                                               |
| 時間帯4件          | `label`、`headline`、`text`、必要に応じ`mood`などの表示文言。時刻・参照猫種との対応は維持                                                                                         |
| クイズ3問          | `q`、各`choices`、`explain`、正誤／進行／結果／やり直しのUI文言                                                                                                                   |
| 画面全域           | ヘッダー、ヒーロー、フロア、ランキング説明、カード、時間帯、クイズ、詳細、フッター、固定UI、言語選択・Cookie保存失敗通知                                                          |
| 支援技術向けの文言 | 意味のある`alt`、`aria-label`、`aria-labelledby`／`aria-describedby`が参照する見出し・説明文、`title`、`sr-only`、`role="status"`内の通知文、ツールチップ、操作案内、SEO metadata |

- `aria-labelledby`／`aria-describedby`の属性値は参照ID、`role`の属性値は役割名であり、翻訳しない。翻訳するのは参照先や要素内の人間向け文言。参照先ID・アンカーIDとの対応を壊さない。
- 既に英語で世界観として機能している`NEKO DISCO`、`STAR POP EXPRESS`等は、機械的に訳さない。固有名詞・団体正式名・文献原題・URLを保持してよいが、その前後の説明・調査条件は英訳する。
- 英語ページ内に日本語の固定UI文字列が残らないよう、**表示条件・未発見／発見済み・音楽4状態・クイズ進捗・モーダル・エラー通知**を含めて網羅する。引用・正式名称などの意図的な日本語例外は一覧で管理する。

### 5.2 英語編集方針 [確定]

- 逐語訳や一文ごとの意味完全一致は不要。コンパクトで自然な英語、少しのユーモア、DJ／ダンスフロアの遊び心を歓迎する。
- 品種の外見・性格の傾向・生活リズム・個体差を過度に断定しない。創作キャラ設定と一般的な猫の事実を混同させない。
- 安全情報（休息、音量、水、遊び等）、出典、調査の母集団・期間・除外条件、クイズの正解関係は変えない。
- 英文に合わせて日本語コピーを短縮・変更しない。**英語の文字列を収めるための折返し・テキスト領域・余白は英語側で調整可**とする一方、日本語既存の改行・演出、猫画像の配置・表示倍率は変更しない。
- 正式な出典名・URLは原表記のままでよい。訳した説明が原出典と別の調査を意味するような意訳は禁止。
- [英語制作の進行案] 全量を一度に翻訳する前に、猫種2〜3件と生態1件で英文のトーンを試作して**一度まとめて**確認する。その後は合意したトーンで同じ領域の残りを作成し、事実確認とデータ検査を行う。一文ずつ承認待ちにしない。

### 5.3 不変の識別子・事実 [確定]

- 猫種・生態のID、12件ずつの存在、ランク・並び、画像・フロア座標・猫スプライトの表示サイズ、クイズの正解位置・関連猫種、出典URL。**英文のテキスト領域の寸法まで固定する意味ではない**。
- 2026年版のアイペット（現・第一アイペット）関連ランキング。**調査上のミックス猫を除き、元の2〜13位をサイト上の1〜12位として表示**すること。
- 調査対象は2025年1月1日〜12月31日に保険の契約を開始した猫であり、国内の全飼育猫を対象とした順位ではないこと。
- 日本語本文・イラストは基本維持。事実や飼育上の注意に問題を発見した場合は、翻訳作業に紛れ込ませず別途報告する。

### 5.4 データ検査と表示構造 [確定した受入条件／設計候補]

- [設計候補] 翻訳文言とID・順位・画像・座標などの共通データを分離し、両言語で同じ識別子を使用する。ID・順位・画像との正しい対応は[確定]。
- [確定] 必須キーの欠落・空白のみの文言・誤った参照・クイズの不一致を型とテストで検出する。**英語未入力時の日本語フォールバック、ダミー英文、型アサーションによる抜け道を完了条件にしない**。意図的な装飾画像の`alt=""`は除外。
- [現行事実] `breeds.indexOf(selected)`はオブジェクト参照同一性に依存する。[設計候補] `{kind, id}`等の安定した選択方式で画像・詳細の対応を保つ。
- [確定] 現行の日本語向け`BreedName`分割や改行を英語へ強制しない。[設計候補／要検証] クライアント／サーバー境界で必要な翻訳データだけを扱い、未使用の両言語データ一括配布を避ける具体的な分割・SSR経路。

## 6. デザイン・アクセシビリティ

### 6.1 デザインの採用基準 [確定]

- 日本語版のヒーロー、ミラーボール、フロア、猫のカード、照明、タイポグラフィ、音楽・モーション操作、固定カプセル、CTA、画面全体のバランスを保持する。英語版の文字組みは第5.2節の範囲で調整してよいが、猫の配置や装飾を変更する許可にはならない。
- 言語切替UIは**配置も形も未決定**。ヘッダー直置き／1段のコンパクトメニュー／他のページ内配置などを、世界観・到達しやすさ・既存操作への干渉で比較し、採用前にユーザーへ提示する。
- スマホは既存ヘッダーの高さ・**1段を第一候補**とする。1段で必要な操作領域・文字表示・アクセシビリティを確保できない場合は、無理に押し込まず、理由と代替案を提示して承認を得る。2段化、既存ボタンの省略、極端な縮小は無断で採用しない。
- PC・320／375／390pxの画面、メニュー展開・フォーカス・ホバー・タップ状態を比較する。幅だけでなく、横向き・safe-area・200%ズーム・英文の長さを確認する。

### 6.2 アクセシビリティ [確定した品質目標／要検証]

- 最初のSSR HTMLでも言語に合う`html lang`、操作の読み上げ名、キーボード導線と可視フォーカスを備える。モーダル・ツールチップ・Sliderと、言語切替後のフォーカスを確認する。

## 7. SEO・初期HTML・キャッシュ

### 7.1 URL別SEO [確定]

- 本番オリジン：`https://nekodisco.party`。
- `/ja`と`/en`はそれぞれ自身をcanonicalにする。両ページに`ja`／`en`の自己・相互`hreflang`、`/`を`x-default`に設定する。
- `html lang`、title、description、OGPのテキスト・言語・URLを言語別にする。既存の日本語文言・faviconは維持する。
- canonical・OGP URLにクエリ／ハッシュを含めず、プレビューURLが本番canonicalへ混入しない。
- **初期HTMLのHTTP取得結果**と、**同一タブのソフト遷移後のDOM／metadata**を別々の受入対象とする。

### 7.2 配信・キャッシュ [確定した安全条件／要検証]

- Cookie・`Accept-Language`で結果が変わる`/`の307を、共有キャッシュが別ユーザーへ再利用しないこと。 [設計候補] `Cache-Control: private, no-store`、補助的な`Vary: Cookie, Accept-Language`。`Vary`のみで安全を宣言しない。
- `/ja`・`/en`はURLで表示言語を確定し、言語判定のために全ページを利用者別の`no-store`にしない。既存の認証等の応答ヘッダーを勝手に削除しない。
- ローカルWorkerで、Cookieと`Accept-Language`を変えた交互・並行アクセス、307 Location、ヘッダー、HTML、ハイドレーション、画像・CSS・音源を検証する。
- Cloudflare配信経路の実キャッシュ、プレビューのアクセス制限／noindexと露出は公開前に別途検証する。許可なくリモートへデプロイしない。ローカル成功だけで本番キャッシュ安全性を保証しない。
- [運用上の注意／要確認] これまでのCloudflare設定では`main`がProductionブランチ。**mainへのmergeは自動的な本番公開につながる可能性があり、ブランチpushもPreview公開につながり得る。** `push`・PR・`merge`の承認を取る際は自動デプロイの影響を合わせて説明し、実際の接続設定を確認する。「merge」と「公開」を無関係な操作とみなさない。
- [公開前の進行案] ローカル確認 → **明示承認を得た**Preview／必要なアクセス制限の確認 → 公開判定と復旧手順の確認 → **本番公開を伴い得る**mainへのmerge、の順に進める。`/`・`/ja`・`/en`の完成した組を**同じリリース成果物**に含め、不完全な言語ルートを先に外部へ公開しない。これは配信先・閲覧者・旧キャッシュが世界中で同時に切り替わることの保証ではない。混在・キャッシュ・戻し方は配信時に確認する。本番固有の挙動は公開後の確認項目として分離し、未検証のまま安全と断定しない。
- [公開前の復旧条件／要検証] 多言語版の公開後に旧日本語単一ページへ戻すと、共有済み`/ja`・`/en`が404になる可能性がある。復旧案には言語別URLへの影響と利用者への影響を明記し、URLの継続が保証できない場合は復旧方法を事前に承認してもらう。`/en`を黙って日本語へ転送する等の仕様変更は行わない。具体的な対応は公開判定時に決め、A/B段階の作業は止めない。

## 8. 実装段階と小PRの計画 [3段階・小PR方針は採用済み／具体的な分割は工程ごとに決定]

### 8.1 方針とPRの大きさ

- これまでの**「日本語データ整備 → 英語データ・基盤準備 → ルート・画面接続」の3段階**は維持する。ただし**3段階＝3本のPRではない**。ユーザーの最新要求に従い、**大きすぎる差分は提出前に分割し直す**。
- 原則、**1PR＝1つの主たるレビュー目的**。大量の翻訳・単純移動・振る舞いの変更・依存更新・デザイン変更を、無関係に1PRへ混ぜない。複数コミットに分けただけでは大きなPRの問題は解消しない。**最後のルート公開PRも例外にしない**。
- PRを始める前に、目的、主な対象ファイル、想定される差分の性質、日本語回帰の観点、完了条件を簡潔に提示する。想定以上に差分や責務が膨らんだら、**完成させてからではなく途中で**分割案を提示する。
- ファイル数や行数だけで機械的に合否を決めない。データ移動は行数が多くても単純な場合がある。ただし、**1回のレビューで変更意図と影響を追えないPRは分割対象**。小さすぎるPRを量産して依存関係だけを増やすことも避ける。
- 独立した小PRは、それ自体の型・必要なテスト・build・影響範囲の回帰を確認でき、**単独で取り込んでも日本語版が壊れず未完成の英語ページが公開されない**構成にする。後続PRにしか関係しない受入条件で、独立した前段PRを無期限に止めない。
- コミット境界とPR境界は別。**コミット・push・PR作成・merge・デプロイはそれぞれAGENTS.mdの承認条件を守る。** 自動デプロイへの影響も第7節に従う。

### 8.2 3段階とレビュー可能な切り方（固定本数ではない）

| 段階                        | 小PRの候補となる独立した主題                                                                                                           | 当該段階で守る境界                                                                                  |
| --------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| **A. 日本語の安全な整理**   | 安定ID・選択参照の整理／猫種の日本語データ分離／生態・時間帯・クイズの日本語データ分離（大きければさらに分割）                         | 画面・BGM・URL・Cookieを変えず、日本語の既存表示と操作を維持                                        |
| **B. 英文と純粋な準備処理** | トーン試作後の英語猫種／英語生態・時間帯・クイズ／日英UI文字列／言語判定・Cookie・metadataの純粋な処理（責務ごとに分割）               | B段階ではルートや言語UIへの接続は行わず、英語データが揃っても日本語の`/`を維持                      |
| **C. 画面とルートの接続**   | 初期の限定Link確認／日本語表示を維持する共通状態／既存`/`画面の辞書参照化／承認済み言語UIの非公開準備／最後のURL・Cookie・metadata接続 | **未完成の`/en`を公開しない**。接続前の準備を小PRに分け、最終ルート切替に無関係な大量修正を残さない |

これは**小PRの分割候補**であり、各スラッシュ区切りを必ず1本ずつのPRにするという意味ではない。実際のファイル変更と依存関係を見て、着手前にレビュー可能な粒度を提示し、承認された単位で進める。**最終接続PRが大きくなる見込みなら、着手前に準備PRへ前倒しできる変更を整理して分割案を示す。**

### 8.3 重要な実装境界と既知の技術リスク

- [実装上の制約] 同じルートの`page.tsx`と`route.ts`を共存させない。A/B段階およびC段階の準備PRを取り込んだ公開サイトは、引き続き現行`/`の日本語画面を維持する。C段階では**外部公開しないローカル作業環境**で完成ルートを接続して確認できる。未完成の`/en`をPreview・本番へ露出させない。最終接続では`/`入口と`/ja`・`/en`を同じ完成版のリリース単位に含め、途中状態の公開を防ぐ。配信・キャッシュ全体の厳密な原子性は保証しない（第7.2節）。
- [設計候補／要検証] 言語ごとの初期SSR `html lang`、metadata更新、Provider／AudioContextの継続を同時に成立させる。成立しない場合、状態保持を縮小せず、限界と代替案を提示して判断を求める。
- [旧スパイクの扱い] 旧Rolldown 1.0.1ではLink不具合の最小再現があり、1.0.2を含む**WASM依存2件も変わった候補構成**で動作成功例があった。現在の`main`には候補overrideがない。**C段階の冒頭、Provider移動やUI接続に先立ち、現行依存の通常buildをローカルWorkerで動かし、最小構成のLinkクリック・ソフト遷移を確認する**。確認対象・合否・終了条件は第8.4節の最初の項目に限定する。この事前確認は完成した実ルートの受入テストを代替しない。Link動作が成立しない場合や準備作業がAGENTS.mdの再評価条件に達した場合は、調査を自動拡大せず、影響・候補対策・次の判断を示して停止する。単純な操作ミスの扱いはAGENTS.mdに従う。旧CDP診断一式を作り直さない。依存変更が必要なら差分とリスクの承認を得る。
- [現行の基準] A段階の最初に、実際に作業を開始する`origin/main`の**コミットSHA**と日本語版の代表的な表示・操作条件を記録する。過去の`main`を無条件に最新基準へ上書きせず、変更があれば差分を確認する。
- [成果の確定] 小PRごとに成果・検証・残るリスク・コミット候補を提示する。**実装許可はコミット許可ではない**。コミット、push、PR作成、merge、公開に必要な承認を省略しない。

### 8.4 C段階の順序と最終接続PRの境界 [分割候補]

1. **着手直後の短い技術確認**：現行依存の通常buildをローカルWorkerで起動し、必要なら**ローカル限定の最小検証ルート**を用意する。**prefetch有効・無効の双方**で、実際のLinkクリックによる遷移、URL更新、フルリロードなしの同一タブ遷移、および既知のnavigation関連エラーが発生しないことを確認する。**両条件を満たしたらこの調査は終了**し、状態保持・初期HTML等は後段の完成ルートで確認する。Link動作が成立しない場合や準備作業がAGENTS.mdの再評価条件に達した場合は、結果と影響・選択肢を報告して停止し、追加のCDP基盤や依存変更へ独断で進まない。単純な操作ミスの扱いはAGENTS.mdに従う。仮ルート・診断を公開用の変更へ混ぜない。
2. **状態の所有場所を整理する小PR**：日本語の`/`を表示したまま、Provider・BGM・発見・クイズ等の継続に必要な構造を整え、日本語回帰を確認する。
3. **辞書参照・UI部品を準備する小PR**：既存`/`の日本語画面を共通辞書参照へ移し、言語選択UIはデザイン承認後に部品として用意する。未完成の言語切替導線や`/en`を公開ページへ接続しない。言語判定・Cookie・metadataの純粋処理はB段階で準備済みとする。
4. **最後の公開ルート接続PR**：準備済みの画面・状態・UI・判定処理を接続し、`/`入口・`/ja`・`/en`を完成した組として受入確認する。**主たる差分はルート接続**とし、ここで大規模な辞書作成・Provider再設計・依存更新・UIデザイン変更を同時に始めない。

上記は固定の4PRではなく、レビュー可能な差分と依存関係に応じて分割する順序の目安。最終接続がなお大きい場合は、開始前に理由・差分・分割可能性を提示する。新しい公開用フラグや仕組みを増やしてまで分割しない。

## 9. 受入条件（仕様との対応）

### 9.0 受入テストを行う工程の境界

- **各小PR**：その差分に直接関係する型・テスト・build・日本語回帰を実行する。完了済みで影響を受けない検証を無理由に全面再実行しない。
- **A段階**：日本語コンテンツ、ID・画像・順位・クイズ正解、変更した操作の回帰を確認。英語ルート・Cookie・RSCの実ブラウザ検証は要求しない。
- **B段階**：英語データとUI文言の完成度、出典・正解関係、言語判定・Cookie等の純粋な関数を検査。公開しない`/en`画面のE2E成功を前提にしない。
- **C段階**：冒頭のLink確認は第8.4節の**prefetch両条件・クリック・URL更新・ソフト遷移・既知エラーなし**を確認したら終了する。準備PRでは日本語`/`の回帰と変更した部品に対応する検証を行い、**最終接続PRでは**実際のURL・Cookie・状態保持・翻訳済みUI・初期SSR・ソフト遷移を別途受入確認する。通常テストでは確認できない点だけ追加調査する。
- **公開判定前**：全体の主要回帰、許可済みPreviewでの表示・アクセス制限・配信・キャッシュ確認。**mainへのmergeが本番公開を伴う可能性**を踏まえて許可を得る。復旧時の`/ja`・`/en`共有URLへの影響と必要な承認を確認する。本番でしか確認できないものは公開後の確認と復旧準備へ分離する。
- 第9節A〜Eの全項目は最終的な完成条件。**すべての項目をすべての小PRに適用しない。** 調査が脱線した場合はAGENTS.mdの強制再評価に従い、合意済み受入条件を無断で削減しない。

## 11. 開発開始の手順と承認境界

1. 本書の**[確定]**事項と**3段階・小PR方針**を開発の基準とする。[要決定]事項は第10節に定めた工程までに確認し、[要検証]事項は該当工程で検証する。未承認の設計候補を確定扱いにしない。
2. `docs/i18n-spec.md`に本書を反映する際も、AGENTS.mdに従い作業ブランチ・既存未コミット変更を確認し、`origin/main`の基準SHAと作業範囲を明示する。ファイルの反映・コミット・pushはそれぞれ承認された範囲で行う。
3. A段階の最初の**小PR**を提案する。目的、影響ファイル、確認方法、コミット境界を簡潔に説明し、合意後に実装を始める。旧スパイクのRSC/CDP調査は前提としない。
4. A/B段階は日本語ページを維持する。C段階は初めに第8.4節の**終了条件を持つ限定Link確認**を行い、状態・辞書参照・UIを日本語版の動作を保った小PRで準備する。最後に完成した`/`・`/ja`・`/en`を同じリリースに含め、**未完成の英語ルートを公開しない**。
5. 調査が長期化した場合はAGENTS.mdの強制再評価を適用し、受入条件を勝手に減らさずに継続価値と選択肢を提示する。
